# PutnamBench benchmark adapter

Drives Asterism against [PutnamBench](https://github.com/trishullab/PutnamBench)
(672 Putnam competition problems, Lean 4). Benchmark tooling, not part
of the framework — same boundary rules as `Benchmarks/minif2f/`.

Roadmap anchor: P1 (2026-H2) WS-B — Phase 1 = 50-problem sanity batch,
**G0 gate (2026-08): ≥40% proved → full 270-problem Phase 2**.

## Protocol decisions

- **Solution abbrevs live in `Defs.lean` with the official answer
  filled in.** Upstream ships `abbrev putnam_X_solution : T := sorry`
  plus the answer as a comment; their `rewrite_solutions.py` textually
  inlines it (the `solutions_replaced` evaluation protocol used by
  prover papers). We express the same thing as a separate reducible
  definition in the author-vouched `Defs.lean` layer instead of
  textual inlining — semantically equivalent (abbrev is reducible),
  provenance-auditable, and the Root statement stays byte-faithful to
  the upstream theorem. Consequence: these are PROVING tasks, not
  answer-finding tasks (same as the published numbers we compare to).
- **Statements are never edited.** Upstream pins Lean v4.27.0; this
  workspace tracks a newer toolchain. Problems whose statements do not
  elaborate here are EXCLUDED and logged by the prep driver, with a
  deterministic same-stratum substitute. See `phase1_report.md`.
- **Line-preserving normalization.** The theorem signature becomes
  `∀ <binders>, <conclusion>` with upstream newlines KEPT — line
  breaks are syntactically significant (`let` bindings inside a
  statement terminate at the line break; one-line collapsing is a
  parse error — putnam_1965_b4). Inline `--` comments between binders
  are stripped (they would pollute textual statement comparisons).
  These are the only two transformations besides the `∀` closure.
- **No per-problem hints** (`Strategic notes` carries only provenance).
  `library: false` — benchmark proofs are not Library material.
- **Stratified sampling**: 12 strata (A1–A6, B1–B6) × 4 + 1 extra each
  for A1/B1 = 50; within a stratum, picks are evenly spaced across the
  year-sorted pool (1962–2025), so difficulty and era are both covered.
- **Falsity**: if a statement is wrong (errata hunting — miniF2F gave
  us 9), the framework's `AttemptDisproof` path produces a
  kernel-checked counterexample and hands back via `RequestUserAmend`;
  the Manifest tells the strategist so explicitly.

## Workflow

```bash
# 1. Clone upstream on demand (gitignored)
git clone --depth 1 https://github.com/trishullab/PutnamBench _ext/putnambench

# 2. Prepare the Phase 1 batch (emit + toolchain validation +
#    substitution + init registration + report)
python Benchmarks/putnambench/prepare_phase1.py [--dry-run]

# 3. Fire the run (operator decision — token cost)
asterism run --scope 'Putnam.%'
```

The adapter can also be used directly for arbitrary subsets:

```bash
python Benchmarks/putnambench/adapter.py \
    --source _ext/putnambench/lean4/src \
    --output ./Problems \
    --names putnam_1962_a1,putnam_2008_b1 \
    --upstream-commit <sha>
```

Outputs `Problems/Putnam/<name>/{Manifest.md, Defs.lean, Root.lean}` —
all three are emitted by the adapter (the post-Phase-6 framework
treats Root/Defs as user-pinned inputs; `init` no longer generates
Root from the Manifest, unlike the early miniF2F era).

## Files

- `adapter.py` — parse upstream `src/*.lean` → Problem dirs
- `test_adapter.py` — fixture tests + full-corpus parse canary
  (canary auto-skips without the clone)
- `prepare_phase1.py` — stratified 50-batch driver (see docstring)
- `phase1_selection.json` / `phase1_report.md` — generated by the
  driver: final selection, exclusions with error evidence, firing
  instructions
- `prep.log` — driver log of the latest prep run

## Removing the batch

```bash
for d in Problems/Putnam/*; do
    python -m Tooling.core.cli reset "Putnam.$(basename $d)"
done
rm -rf Problems/Putnam
```
