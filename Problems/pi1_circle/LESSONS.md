<!-- LESSONS_BEGIN -->
- For `f.HomotopicRel g {0,1}` between two continuous maps into ℝ (or any real TVS) with matching endpoints, do NOT build the homotopy from scratch — `ContinuousMap.Homotopy.affine f g : f.Homotopy g` (in `Topology/Homotopy/Affine.lean`) gives the straight-line `lineMap (f x) (g x) t`, and the rel-property at `x ∈ {0,1}` collapses via `Path.segment_same` (`segment a a = .refl a`) after rewriting with the endpoint hypotheses; total ~10 lines.
- To extract endpoint values from `cov.liftPath_trans` (which returns a Path equality, not a function equality), use `DFunLike.congr_fun (cov.liftPath_trans hpe γ γ') 1 |>.trans (Path.target _)` — plain `congr_fun` fails on the Path-level equation, and `rw` is blocked by the dependent proof argument `hpe`; this yields `liftPath (γ.trans γ') 0 _ 1 = liftPath γ' (Γ 1) _ 1` directly (same trick used in Mathlib's `monodromy_trans_apply`).
- To push a ℝ-lift-level `ContinuousMap.HomotopicRel` down to Circle, apply `.comp_continuousMap ⟨Circle.exp, Circle.exp.continuous⟩` then rewrite `(⟨exp,_⟩.comp Γ) = γ.toContinuousMap` — `cov.liftPath_lifts` is a function-level equality (`exp ∘ Γ = γ`), so bridge to ContinuousMap.comp via `DFunLike.ext`/`ContinuousMap.ext` + `congrFun (cov.liftPath_lifts ..) t`.
- Sibling proved lemmas (e.g. `int_mul_two_pi_inj`, `lift_endpoint_mem_two_pi_int`) are NOT auto-imported into `_strategy_s<id>.lean` despite the "framework auto-appends imports" hint — cite them explicitly via `import Problems.pi1_circle.proofs.L_<slug>` at the top of `patch.lean` (mirror `_strategy_s10691.lean`) or lake build fails with `Unknown identifier`.
- `Path.Homotopic.setoid` is declared `attribute [local instance]` inside Mathlib's `Path.Homotopic` namespace, so `γ ≈ γ'` fails to synthesize `HasEquiv (Path x y)` from outside — when supplying the soundness proof to `Quotient.lift` over `Path.Homotopic.Quotient`, state the hypothesis as `Path.Homotopic γ γ'` (or `γ.Homotopic γ'`) directly.
- To show `liftPath f e hpe = someMap`, use `IsCoveringMap.eq_liftPath_iff'` (proves `someMap = liftPath ...` by supplying `p ∘ someMap = f` and `someMap 0 = e`) rather than `rw`-ing a path-equality, which fails because the dependent proof argument `hpe` blocks the motive typecheck.
- `induction a using Quotient.ind` works directly on `a : FundamentalGroup Circle 1` (no manual `End`/`FundamentalGroupoid` unfolding) — exposes a `Path 1 1` representative `γa` with `a` defeq to `⟦γa⟧`, useful for transporting quotient-level lemmas (`Path.Homotopic.Quotient.trans`, refl) into group-level goals.
- `FundamentalGroup X x = End (FundamentalGroupoid.mk x)` and `End.mul_def` gives `a * b = b ≫ a` (reversed), so `(a * b).toPath = b.toPath.trans a.toPath` — when wiring `MonoidHom.map_mul'` through `monodromy_trans_apply` or `Path.Homotopic.Quotient.trans`, expect arguments in swapped order.
- `Path.Homotopy` is an `abbrev` for `ContinuousMap.HomotopyRel p₀.toContinuousMap p₁.toContinuousMap {0,1}`, so `h : γ.Homotopic γ'` is accepted directly (no conversion needed) by `IsCoveringMap.liftPath_apply_one_eq_of_homotopicRel` — pass it as the `HomotopicRel` argument.
- Goals here use `π` (needs `open Real` in patch); bridge `Circle.exp r = 1 ↔ ∃ n : ℤ, r = n * (2 * π)` is `Circle.exp_eq_one`, and `Circle.isCoveringMap_exp.liftPath_lifts/zero` give `exp ∘ Γ = γ` and `Γ 0 = 0`.
