- To reuse a proved Forward-toolkit alias (e.g. `homotopy_invariant_contour_integral` / `closed_path_integral_zero_on_ball` / `principal_part_extraction_at_singularity`) from a Backward `patch.lean`, direct citation fails lake build with `Unknown identifier` — the framework's auto-import for `_strategy_*.lean` only covers slugs declared via `new_<slug>.lean` in attempts_dir, NOT arbitrary proved siblings, despite the Backward prompt's "Cite any sibling goal freely" hint; workaround is to ship a uniquely-named one-line Builder wrapper sub-goal (e.g. `<purpose>_step_wrapper`) with the alias's exact signature and cite the wrapper from patch.lean — the wrapper's `L_*.lean` DOES get the proved-sibling auto-import for free (as in `L_path_integral_eq_diff_on_ball.lean` auto-importing `L_path_integral_eq_primitive_diff`).
- For integrand-continuity / FTC goals over `Icc 0 1` whose integrand uses `deriv γ t / ...` with only `ContDiffOn ℝ 1 γ (Icc 0 1)` as hypothesis, `deriv γ` can carry junk values at endpoints (since `DifferentiableAt ℝ γ 0/1` need not follow from `DifferentiableWithinAt`), so `ContinuousOn (fun t => deriv γ t / (γ t - a)) (Icc 0 1)` is generally false and `fun_prop` fails at the endpoints; swap to `derivWithin γ (Icc 0 1)` which IS continuous on `Icc` via `ContDiffOn.continuousOn_derivWithin uniqueDiffOn_Icc_zero_one le_rfl`, transfer integrals via `intervalIntegral.integral_congr_ae` (the two agree on `Ioo 0 1`, hence a.e. on the integration interval), then push the conclusion back through `DifferentiableOn.congr` — same pattern applies whenever the goal shape is `DifferentiableOn` of a `∫₀ˢ`-antiderivative whose integrand mentions `deriv γ`.
- For FTC-along-path goals `(∫ t in 0..1, f (γ t) * deriv γ t) = F (γ 1) - F (γ 0)` with `ContDiffOn ℝ 1 γ (Icc 0 1)` + `∀ z ∈ U, HasDerivAt F (f z) z` + `MapsTo γ (Icc 0 1) U`, decompose via `intervalIntegral.integral_eq_sub_of_hasDerivAt_of_le zero_le_one` into (a) `ContinuousOn (fun t => F (γ t)) (Icc 0 1)`, (b) interior chain rule `∀ t ∈ Set.Ioo 0 1, HasDerivAt (fun s => F (γ s)) (f (γ t) * deriv γ t) t` (use `Icc_mem_nhds ht.1 ht.2` to unlock `(hγC1.differentiableOn le_rfl t (mem_Icc_of_Ioo ht)).differentiableAt`, then `HasDerivAt.comp`), and (c) `IntervalIntegrable (fun t => f (γ t) * deriv γ t) volume 0 1` — the Ioo-interior restriction sidesteps the derivWithin/junk-endpoint trap from earlier lessons entirely, since `Icc 0 1 ∈ nhds t` for interior `t`.
- For `intervalIntegral.integral_congr_ae`, after `apply` the goal is `∀ᵐ t ∂μ, t ∈ Ι a b → P t` (unrestricted ae on `μ`, NOT a `μ.restrict`-ae goal), so use `filter_upwards` on `volume.ae` directly; when `P t` only holds on `Ioo a b` (endpoint `b` excluded because `DifferentiableAt` fails there), prove `hne : ∀ᵐ t ∂volume, t ≠ b` via `rw [MeasureTheory.ae_iff]; simp [MeasureTheory.measure_singleton]`, then `filter_upwards [hne] with t hne_t ht_uIoc` and `rw [Set.uIoc_of_le hab] at ht_uIoc` to get `t ∈ Ioc a b`, then `lt_of_le_of_ne ht_uIoc.2 hne_t` for `t ∈ Ioo a b`; additionally `HasDerivAt.scomp` (like `HasDerivWithinAt.scomp`) takes an explicit point `x` — use `hg.scomp x hh` — and for ℝ→ℂ goals the result `(r : ℝ) • (z : ℂ)` needs `rw [Algebra.smul_def]; norm_cast` to become `(r : ℂ) * z`.
- For Builder `patch.lean`, `import Problems.residue_thm.proofs.L_<slug>` resolves correctly and `theorem new_name {args} ... := proved_sibling args` compiles with near-zero elaboration — this contrasts with lesson 1 (Backward patches cannot cite siblings directly); whenever the goal's signature exactly matches an already-proved `L_*.lean` sibling, use this alias pattern to eliminate timeout risk entirely rather than re-elaborating the proof body.
- For `DifferentiableOn ℝ (fun τ => ∫ t in 0..1, g τ t) (Icc 0 1)` parameter-dependent-integral goals from `ContDiffOn ℝ n (uncurry g) (Icc 0 1 ×ˢ Icc 0 1)`, Mathlib's parametric Leibniz lemmas (`intervalIntegral.hasDerivAt_integral_of_dominated_loc_of_deriv_le`, `hasFDerivAt_integral_of_dominated_loc_of_lip`, `hasFDerivAt_integral_of_dominated_of_fderiv_le` in `Mathlib.Analysis.Calculus.ParametricIntervalIntegral`) all require `s ∈ 𝓝 x₀`, so they cannot deliver `DifferentiableWithinAt` at boundary τ ∈ {0, 1} (same `Icc 0 1 ∉ nhds 0` trap as the `deriv γ`-at-endpoints lessons applied to the parameter side); the parent constancy strategy should NOT route through `constant_of_derivWithin_zero` (which forces DifferentiableOn on closed Icc) but instead split into `ContinuousOn J (Icc 0 1)` via `intervalIntegral.continuous_parametric_intervalIntegral_of_continuous'` + `HasDerivAt J 0` on `Ioo 0 1` (where `Icc 0 1 ∈ 𝓝 τ` unlocks parametric Leibniz) + `IsOpen.is_const_of_deriv_eq_zero` on preconnected open `Ioo 0 1`, then extend the resulting Ioo-constancy to Icc via continuity.
- For path-concatenation integral-split goals `∫ Q(γ)·γ' = ∫ Q(α')·α'' + ∫ Q(β')·β''` with arbitrary `Q : ℂ → ℂ`: `intervalIntegral.integral_comp_mul_right/left` is UNCONDITIONAL (proved via `MeasurableEmbedding` from a homeomorphism, no `IntervalIntegrable` needed), but `intervalIntegral.integral_add_adjacent_intervals` REQUIRES `IntervalIntegrable`; this asymmetry makes the goal FALSE for arbitrary Q — the RHS can be nonzero via unconditional substitution while the LHS = 0 when one half-interval piece of the piecewise integrand is non-integrable (e.g., α'(t)=(1−t)², β'(t)=(1+i)t², Q=1/Im(z) near 0) — decline immediately unless `Continuous Q` or `ContinuousOn Q (image γ)` is in scope to supply `IntervalIntegrable` via the product-continuity route.
- For chain-rule `derivWithin` goals mixing ℝ→ℝ inner with ℝ→ℂ outer on `Icc 0 1`, `derivWithin.scomp` silently fails to unify the scalar-field parameters, leaving spurious `DifferentiableWithinAt` goals unsolved; instead use `HasDerivWithinAt.scomp` via dot notation `houter.scomp x hinner h_maps` (outer first, then explicit point `x`, then inner, then MapsTo) and recover `derivWithin` via `hcomp.derivWithin huniq`; also `ContDiffOn.differentiableOn` takes `(hn : n ≠ 0)` not `(hn : 1 ≤ n)` — pass `one_ne_zero` or `(by norm_num)`, and `uniqueDiffOn_Icc_zero_one` (not `uniqueDiffWithinAt_Icc`) gives `UniqueDiffWithinAt ℝ (Icc 0 1) x` for `x ∈ Icc 0 1`.
- For `derivWithin (fun t => c + ∫₀ᵗ f) (Icc a b) t` goals at ALL `t ∈ Icc a b` including boundary (where `Icc a b ∉ 𝓝 t`), synthesize `FTCFilter t (𝓝[Icc a b] t) (𝓝[Icc a b] t)` by `haveI : Fact (t ∈ Icc a b) := ⟨ht⟩` (activates `intervalIntegral.FTCFilter.nhdsIcc`), then `intervalIntegral.integral_hasDerivWithinAt_right ((hf.mono hsub).intervalIntegrable) ⟨Icc a b, self_mem_nhdsWithin, hf.aestronglyMeasurable measurableSet_Icc⟩ (hf.continuousWithinAt ht)` where `hsub : uIcc a t ⊆ Icc a b`; fold in the additive constant via `(hasDerivWithinAt_const.add hhas)` and discharge `0 + f t = f t` with `simpa`; recover `derivWithin` via `.derivWithin (uniqueDiffOn_Icc_zero_one t ht)` — this uniform pattern (no interior/boundary case split) appears in `differentiable_on_integral_of_continuous_on` and works whenever `ContinuousOn f (Icc a b)` holds.
- A ball cover of a closed C¹ path into an open set U does NOT suffice to prove ∫ g(γ)·γ' dt = 0 without a null-homotopy or simply-connected hypothesis — counterexample: U = ℂ\{0}, g = 1/z, γ = unit circle satisfies all hypotheses of `apb_cover_step_wrapper` / `analytic_path_int_zero_given_ball_cover` (IsOpen U, AnalyticOn g U, ContDiffOn γ, MapsTo, γ 0 = γ 1, finite ball cover ⊆ U) but gives integral 2πi ≠ 0 (winding number 1 around 0); any sub-goal with that exact signature (ball-cover data only, no homotopy grid or SimplyConnectedSpace) should be declined `unprovable` immediately, and the parent strategy must pass the null-homotopy data into the sub-goal signature.
